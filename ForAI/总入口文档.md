## Designer

- [产品设计草案](Designer/产品设计草案.md)  
  何时阅读：需要了解产品定位、MVP 范围、功能优先级、主题体验及后续迭代边界时。

- [数据可视化与正反馈设计](Designer/数据可视化与正反馈设计.md)  
  何时阅读：设计首页与分析页的数据展示、财富目标反馈、主题图表或非羞耻化反馈时。

- [MVP 页面与用户流程设计](Designer/mvp页面与用户流程设计.md)  
  何时阅读：讨论首次引导、渐进式建档、页面信息架构、“更新资产近况”及关键用户闭环时。

- [UI 设计稿索引](Designer/UI设计稿/README.md)  
  何时阅读：查看已确认 UI 图纸、视觉基准、必须保留要点及尚待细化的设计边界时。

- [MVP 完整 UI 图纸与自检记录](Designer/UI设计稿/MVP完整UI图纸与自检记录.md)  
  何时阅读：统一验收八组 MVP 高保真图纸，或实施前核对每组产品约束、修订与自检结论时。

## Coder

- [技术选型](Coder/技术选型.md)  
  何时阅读：评审 Flutter 四端路线、MVP 与第二版架构、前后端边界、项目结构或待定依赖时。

- [数值模型与数据字典](Coder/数值模型与数据字典.md)  
  何时阅读：设计数据对象、不可变快照、时间聚合、财富目标或指标计算口径时。

## 推荐阅读路径

1. 先阅读仓库总入口 [README](../README.md)，了解项目定位、当前阶段和总体边界；
2. 阅读 [产品设计草案](Designer/产品设计草案.md)，建立产品范围认知；
3. 阅读 [技术选型](Coder/技术选型.md)，了解架构分期与技术约束；
4. 阅读 [数值模型与数据字典](Coder/数值模型与数据字典.md)，统一数据和指标口径；
5. 阅读 [MVP 页面与用户流程设计](Designer/mvp页面与用户流程设计.md)，理解页面结构与主流程；
6. 最后按具体任务查阅 [数据可视化与正反馈设计](Designer/数据可视化与正反馈设计.md) 或后续新增的专题文档。

## 文档维护约定

- 产品定位、功能范围、交互与视觉设计文档由 Designer 维护；
- 技术架构、技术选型、数据模型与实施规划文档由 Coder 维护；
- 计划、里程碑、任务拆分、风险和决策记录由 PM 维护；
- 新增、移动或重命名协作文档时，必须同步更新本索引。
