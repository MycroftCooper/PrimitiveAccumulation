# 数值模型与数据字典

> 本文档用于开发前审阅，定义已确认产品需求中的概念数据模型、时间规则和指标口径。本文不是 SQL 建表设计，也不指定 ORM 或具体业务代码实现。

## 1. 目的与边界

项目同时管理两类性质不同的数据：

- **资产负债表**：某一真实时点的资产与负债存量；
- **月度现金流基线**：用户主动维护的稳定收入、刚性支出，以及可选的基础生活费估计。

产品不做逐笔记账，不保存每笔日常消费，不接入银行、券商或理财平台 API，也不自动追踪行情或实时市值。

以下三个概念必须严格区分，不能混用：

- **净资产变化**：两个实际资产负债快照之间净资产账面值的差额；
- **投资收益**：投资产生的收益。MVP 缺少自动行情、持仓及完整资金流数据，不能由净资产变化直接推导；
- **月度现金流结余**：根据稳定收入与支出基线计算的月度结余，不等于两个快照之间的净资产变化。

## 2. 用户主动录入的数据对象

| 对象 | 必填字段 | 可选字段 | 用途 |
| --- | --- | --- | --- |
| 资产空间 `FinancialSpace` | 空间标识、空间名称、空间类型 | 空间说明 | MVP 使用个人空间；概念模型为未来家庭或组织共享空间预留。 |
| 分类 `Category` | 分类标识、资产或负债一级属性、分类名称、排序 | 父分类 | 组织资产和负债条目，支持层级及可扩展分类。 |
| 财务条目 `FinancialItem` | 条目标识、名称、所属机构或平台、资产或负债、分类、创建日期 | 形成来源、币种、流动性标识、估值方式、利率、月还款额、到期日、担保物、归属、备注、关闭状态 | 描述一项具体资产或负债的稳定元数据。具体金额不直接存为条目元数据，由快照条目记录。 |
| 资产负债快照 `BalanceSnapshot` | 快照标识、实际生成日期时间、用户触发更新 | 无 | 表示用户在真实时间点提交的一次完整资产负债状态；历史快照不可修改。 |
| 快照条目 `BalanceSnapshotEntry` | 所属快照、财务条目、该时点余额或估值 | 无 | 记录每项资产或负债在该快照时点的金额，使当期资产负债表可完整重建。 |
| 月度现金流基线 `RecurringCashFlow` | 记录标识、类型、名称、金额、频率、起始日期 | 结束日期 | 记录固定收入、刚性支出或可选基础生活费估计，并由系统折算为月金额；不记录每笔日常消费。 |
| 投资决策记录 `InvestmentDecision` | 记录标识、买入或卖出、日期、金额、买卖理由 | 关联投资条目、数量、标的、计划、实际结果、复盘备注 | 用于交易纪律与复盘，不计算实时持仓或自动收益。 |
| 财富目标 `WealthGoal` | 目标名称、目标净资产金额、设定日期 | 目标日期、主题或庆祝偏好 | 以设定日真实净资产作为起点基线，追踪用户向目标净资产前进的距离。状态与完成日期由系统记录。 |
| 用户偏好 `UserPreference` | 基准货币、展示时间颗粒度 | 提醒配置、主题 | 基准货币用于统一计算与展示；展示时间颗粒度控制趋势查看方式。提醒和主题仅在此列示，不在本文展开。 |

### 2.1 资产空间 `FinancialSpace`

MVP 默认只有用户的个人空间。模型保留空间概念，以便未来在每人独立账号的前提下支持家庭或组织的共享资产空间与成员权限。

### 2.2 分类 `Category`

分类首先区分资产与负债，并允许使用父分类形成可扩展层级。

资产分类示例：

- 流动资产；
- 可投资资产；
- 不动产或实物资产；
- 其他资产。

负债分类示例：

- 短期负债；
- 长期负债；
- 有担保负债；
- 无担保负债。

以上是初始示例，不限制后续扩展分类。

### 2.3 财务条目 `FinancialItem`

财务条目描述具体资产或负债，例如某机构中的存款、投资账户、房产或贷款。条目保存相对稳定的描述信息，不直接保存“当前金额”。

条目的金额或估值必须进入 `BalanceSnapshotEntry`。这样可以保留每次真实更新的历史状态，避免条目元数据被覆盖后丢失历史。

### 2.4 资产负债快照与快照条目

`BalanceSnapshot` 表示用户触发并提交的一次更新。其实际生成日期时间必须保留，历史记录不可修改。

用户更新时只需要修改发生变化的条目。系统将未修改条目上一次有效的余额或估值自动沿用到新快照，并为新快照生成完整的 `BalanceSnapshotEntry` 集合。因此，每一份快照都可以独立重建当期完整资产负债表。

### 2.5 月度现金流基线 `RecurringCashFlow`

记录类型仅包括：

- 固定收入；
- 刚性支出；
- 可选的基础生活费估计。

用户填写金额和频率，系统统一折算为月金额。该对象只表示相对稳定的月度基线，不存储逐笔工资到账、账单支付或日常消费。

### 2.6 投资决策记录 `InvestmentDecision`

投资决策记录可以选择关联某个投资类财务条目，但不强制关联。买入和卖出分别记录日期、金额与理由，并可补充数量、标的、计划、实际结果和复盘备注。

该对象只用于纪律建立与事后复盘，不承担实时行情、自动持仓或自动投资收益计算。

### 2.7 财富目标 `WealthGoal`

用户创建财富目标时，必须填写：

- 目标名称；
- 目标净资产金额；
- 设定日期。

目标日期可选。系统以设定日期对应的真实净资产作为起点基线，并记录目标状态（进行中、已完成或归档）及完成日期。主题或庆祝偏好可以作为可选信息简单记录。

目标起点必须对应真实快照。若设定日期当天存在多份快照，采用当天最后一次真实快照；若没有可用的真实快照，则不能虚构起点基线，应要求用户先生成快照或明确显示无法建立目标进度。

### 2.8 用户偏好 `UserPreference`

- **基准货币**：作为汇总计算和展示的统一货币口径；
- **展示时间颗粒度**：用户查看趋势时选择日、周、月、季度、年或自定义区间；
- **提醒**：简单保存提醒相关偏好；
- **主题**：简单保存当前主题相关偏好。

本文只定义与计算直接相关的基准货币和展示时间颗粒度，不展开提醒与主题的产品实现。

## 3. 快照与时间聚合规则

### 3.1 底层存储规则

- 底层只保存带真实日期时间的不可变快照；
- 不因日、周、月、季度或年等展示方式重复保存多份聚合数据；
- 历史快照不可修改；
- 趋势图连接真实记录点，不虚构快照之间发生的交易、现金流或估值变化。

### 3.2 查看时聚合

用户查看数据时，可以选择：

- 日；
- 周；
- 月；
- 季度；
- 年；
- 自定义区间。

系统根据真实快照现场聚合。每个存在记录的周期，取该周期内最后一次真实快照作为该周期的收盘状态。

没有任何快照的周期不补值、不插值，也不伪造数据点。自定义范围必须清楚标注实际取值对应的真实快照日期时间，避免将范围边界误解为数据生成时间。

## 4. 自动计算指标

### 4.1 资产负债规模

| 指标 | 公式 | 含义与边界 |
| --- | --- | --- |
| 总资产 | `Σ 当前快照中所有资产条目的余额或估值` | 某个实际快照时点的资产总额。 |
| 总负债 | `Σ 当前快照中所有负债条目的余额` | 某个实际快照时点的负债总额；以正数汇总。 |
| 净资产 | `总资产 - 总负债` | 某个实际快照时点的账面净资产。 |
| 净资产变化 | `本次快照净资产 - 上次实际快照净资产` | 表示两次实际快照之间的账面变化，不等同于投资收益或现金流结余。首次快照没有上次值时不计算。 |
| 阶段净资产增长率 | `(本次快照净资产 - 上次实际快照净资产) / 上次实际快照净资产` | 表示相对上次实际快照的百分比变化。上次净资产小于等于零或分母无法合理解释时，不显示百分比率，只显示金额变化和说明。 |

### 4.2 结构与集中度

| 指标 | 公式 | 含义与边界 |
| --- | --- | --- |
| 资产配置 | `某资产分类金额 / 总资产` | 展示各资产分类在总资产中的占比。总资产为零时不计算。 |
| 负债结构 | `某负债分类金额 / 总负债` | 展示各负债分类在总负债中的占比。总负债为零时不计算。 |
| 投资资产占比 | `可投资资产金额 / 总资产` | 描述投资类资产占全部资产的比例。总资产为零时不计算。 |
| 单一资产集中度 | `某一资产条目金额 / 总资产` | 描述单一资产条目对总资产的集中程度。总资产为零时不计算。 |
| 总负债率 | `总负债 / 总资产` | 描述负债相对于资产的规模。总资产为零时不计算。 |

### 4.3 月度现金流基线

不同频率的记录先按确定的折算规则换算为月金额，再参与以下计算。

| 指标 | 公式 | 含义与边界 |
| --- | --- | --- |
| 月固定收入 | `Σ 固定收入的月折算金额` | 用户主动维护的稳定月收入基线，不代表某月实际到账流水。 |
| 月刚性支出 | `Σ 刚性支出的月折算金额` | 用户主动维护的必须承担的稳定月支出基线，不含逐笔日常消费。 |
| 月基础生活费估计 | `Σ 基础生活费估计的月折算金额` | 可选的基础生活开销估计；缺少时保持缺失状态，不自动猜测。 |
| 月度固定结余 | `月固定收入 - 月刚性支出` | 只基于固定收入和刚性支出的基线差额，不等于实际月度收支或净资产变化。 |
| 估计必要结余 | `月固定收入 - 月刚性支出 - 月基础生活费估计` | 在用户提供基础生活费估计后，描述覆盖必要开销后的估计结余；缺少估计时显示“数据不足”。 |

### 4.4 偿付压力与安全垫

| 指标 | 公式 | 含义与边界 |
| --- | --- | --- |
| 债务偿付压力 | `每月债务还款额合计 / 月固定收入` | 描述稳定收入用于偿债的比例。月固定收入为零时不计算。 |
| 每月必要支出 | `月刚性支出 + 月基础生活费估计` | 用于安全垫计算。缺少基础生活费估计时显示“数据不足”，不编造数值。 |
| 现金安全垫（月） | `流动资产 / 每月必要支出` | 描述当前流动资产按估计必要支出可以覆盖的月数。缺少基础生活费估计或每月必要支出为零时不计算。 |

### 4.5 财富目标进度

目标进度衡量的是当前净资产相对目标设定时基线的前进距离，而不是简单用当前净资产除以目标金额。

`目标进度 = (当前净资产 - 设定时基线净资产) / (目标净资产 - 设定时基线净资产)`

计算与展示边界：

- 目标净资产必须高于设定时基线，目标小于或等于基线时无法形成有意义的前进区间，应要求用户重新设定目标或显示“不适用”；
- 起点为负净资产时，只要目标高于基线且真实基线明确，仍按前进距离计算，不使用“当前净资产 / 目标净资产”的误导性口径；
- 当前净资产低于基线时，应如实显示尚未向目标前进或出现回撤，不使用羞耻化表达；
- 当前净资产超过目标时，应记录目标已经达到或超过，不以异常百分比制造误导；
- 起点基线缺失、目标区间无效或其他条件导致计算无法解释时，显示“不适用”并要求用户重新设定或补充真实快照。

### 4.6 年化财富变化速度

“年化财富变化速度”仅作为长期分析指标，描述起点与终点真实净资产账面变化折算后的年化等效速度。它可以包含工资积累、还债、新增投入和市场估值变化，因此：

- 不能称为“年化收益率”；
- 不代表投资收益；
- 不能预测未来；
- 不能用于替代需要完整现金流、持仓成本和交易记录的严谨投资收益率。

在数据条件适合时，可基于起点与终点净资产及实际时间跨度计算年化等效变化：

`年化财富变化速度 = (终点净资产 / 起点净资产) ^ (一年天数 / 实际间隔天数) - 1`

仅当起点净资产为正、终点净资产和时间跨度使计算可解释、跨度足够且数据质量适合时展示。起点净资产小于等于零、间隔过短、数据不足或结果容易误导时隐藏，不强行给出百分比。

MVP 不设计严谨的投资年化收益率，因为没有完整现金流、持仓成本和自动交易数据基础。

### 4.7 通用计算与展示边界

- 任一比例的分母为零时不计算，不显示无穷大或伪造百分比；
- 净资产为负时，不使用容易误导的净资产百分比变化，应优先展示绝对金额变化及真实快照日期；
- 缺少必要输入时显示“数据不足”，不自动填补或猜测；
- 所有指标用于财务状况描述、自我观察和学习，不构成投资建议。

## 5. 增长归因边界

没有额外用户标记或足够数据时，两次快照间的净资产差额只能称为“账面变化”，不能自动命名为投资收益、储蓄增长或其他具体归因。

可能影响净资产变化的因素包括：

- 新增储蓄；
- 偿还负债；
- 市场估值变化；
- 补录或修正此前遗漏的资产负债；
- 汇率变化。

MVP 不擅自判断这些因素各自造成的影响，也不自动拆分增长归因。

## 6. MVP 必填最小集与渐进填写

新用户采用渐进式建档，先录入少量关键资产或负债条目，尽快形成第一份可用快照；后续可以逐步补齐分类、条目和可选元数据。产品不得要求用户首次使用时一次填完完整资产负债表。

最小填写原则：

- 只要求创建关键条目所需的必填字段；
- 条目的余额或估值在首次快照中填写；
- 形成来源、币种、流动性、利率、还款信息、担保物、归属和备注等信息可后补；
- 月度现金流基线可在资产负债建档后渐进补充；
- 缺少可选字段时，相关指标显示“数据不足”或暂不计算，不编造数据。

## 7. 第二版与未来预留

- MVP 以本地 SQLite 为唯一事实来源；
- 只有用户主动开启第二版云存档后，本地规范数据才同步到服务器；
- 未来共享资产空间与成员权限基于 `FinancialSpace` 等规范对象扩展；
- AI 资产负债分析、投资复盘和 OCR 辅助录入读取同一套规范数据；
- AI、OCR、同步和共享能力不得改写或破坏不可变快照历史；
- 本文只定义概念模型与指标口径，不设计 SQL 字段，不锁定 ORM。
